# Деплой на Pterodactyl (FrienWorld)

Сервер: панель `panel.frienworld.space`, сервер `b7f95b74`, egg **Node.js generic**, порт `srv3.frienworld.space:40070`.
Бот работает через long polling; открытый порт нужен только подписке на календарь (маленький HTTP-сервер, HTTPS не требуется).

## Что лежит на сервере

```
/home/container
├── index.js          # лаунчер: запускает dist/main.js, при Node < 22.19 скачивает портативный Node 22 в .runtime/
├── dist/             # собранный бот (npm run build)
├── package.json      # зависимости ставятся стартовым скриптом egg'а (npm install)
├── .env              # секреты, создаётся вручную в файловом менеджере панели
└── data/             # SQLite-база (vish-bot.sqlite), бэкапится копированием файла
```

Стартовая команда egg'а уже подходит: `npm install` + `node /home/container/index.js` (переменная `JS_FILE=index.js`).

## Что добавить в `.env` после обновления (раунд 3)

| Переменная | Значение | Что даёт |
|---|---|---|
| `POLL_CRON_BUSY` | `*/6 7-21 * * 1-6` | опрос портала раз в 6 минут (было 5) |
| `PUBLIC_URL` | `http://srv3.frienworld.space:40070` | кнопка «Подписка» в календаре: телефон сам обновляет расписание |
| `PUBLIC_URL_FALLBACK` | второй HTTPS-адрес бота | запасной для ссылок подписки: бот раз в 5 минут проверяет основной и, если тот не отвечает, выдаёт ссылки через запасной |
| `PORTAL_LOGIN` / `PORTAL_PASSWORD` | учётка портала | полный справочник преподавателей и их очные пары; без неё бот знает только преподавателей дистанционных пар |
| `POSTER_THEME` | `midnight` \| `editorial` \| `brutalist` \| `timeline` | оформление постеров |

Кнопка «🎥 Записывать мою группу» (форма заявки на запись, этап 2) показывается в «🗂 Ещё» только когда публичный адрес — HTTPS (`PUBLIC_URL` или запасной) и задан `SLIDES_TOKEN`: Telegram открывает Mini App только по HTTPS.

Порт слушается автоматически: Pterodactyl передаёт его в `SERVER_PORT`, отдельная переменная не нужна. `PUBLIC_URL` нужен только для того, чтобы бот показал ссылку.

## Что добавить в `.env` после обновления (раунд 5)

| Переменная | Значение | Что даёт |
|---|---|---|
| `POISK` | `TRUE` \| `FALSE` | глобальный поиск студентов. `FALSE` — раздела нет вообще: ни кнопки в «Др. группы», ни кнопки в потоке, ни команды `/poisk`, ни колбэков |
| `POISK_DB` | `./data/students.csv` | файл со студентами (ФИО + группа). Кладётся ТОЛЬКО на сервер, в git его нет |
| `POISK_DAILY_LIMIT` | `30` | сколько раз в сутки один человек может искать людей (0 — без лимита; админы без лимита всегда) |

Лимиты ИИ теперь меняются прямо из бота: «Админка → 🤖 Лимиты ИИ» или `/ailimit user 25`, `/ailimit global 1000`, `/ailimit boost 200` (разово в общий бюджет на сегодня), `/ailimit boost user 5` (каждому на сегодня), `/ailimit reset`. Значения из `.env` остаются значением по умолчанию, к которому возвращает «♻️ Как в .env».

### Реестр студентов для «сыска»

Файл с людьми **никогда не коммитится в GitHub** — он едет прямо на сервер:

1. Собрать CSV из выгрузок Excel: `node scripts/students-from-xlsx.mjs data/students.csv реестр.xlsx база.xlsx`
   (скрипт читает только два столбца — ФИО и группу; телефоны, почты, баллы и документы он не открывает и в файл не пишет; имён в консоль не печатает).
2. Залить `students.csv` в панели в `/home/container/data/students.csv`.
3. В `.env`: `POISK=TRUE`, `POISK_DB=./data/students.csv`.
4. Проверить в боте: `/health` → строка «Сыск (поиск студентов)» покажет, сколько человек прочитано и сколько поисков было за сегодня.

Файл можно менять на ходу: бот замечает новый `mtime`/размер и перечитывает его сам, перезапуск не нужен.
Формат — `ФИО;Группа` (первая строка заголовок). Понимаются также JSON (`[{"fio":…,"group":…}]`) и SQLite-файл с таблицей, где есть столбцы ФИО и группы.

### Второй сервер: запись вебинаров

`recorder/` — самостоятельный сервис с браузером внутри. Ему нужно ≥ 1,5 ГБ памяти и Chromium, поэтому он живёт не рядом с ботом, а на своём сервере. Принимает слайды бот (`POST /slides` на его HTTP-порту), так что записывалке ни домен, ни открытый порт не нужны — только выход в интернет.

**Вариант А — VPS (Docker, выкладка по SSH).** GitHub сам собирает образ на сервере и перезапускает контейнер после каждого мёржа в `main`.

1. На VPS (под root): создать `/opt/vish-recorder/.env` по образцу `recorder/.env.example` (значения без кавычек). Docker деплой поставит сам, если его нет (официальный `get.docker.com`); памяти нужно ≥ 1,5 ГБ — на меньшей машине добавить swap.
2. Ключ для деплоя — на своём компьютере: `ssh-keygen -t ed25519 -N "" -f vish-deploy`. Содержимое `vish-deploy.pub` дописать на VPS в `/root/.ssh/authorized_keys`.
3. GitHub → Settings → Secrets and variables → Actions → New repository secret:
   - `RECORDER_SSH_HOST` — IP сервера;
   - `RECORDER_SSH_KEY` — всё содержимое файла `vish-deploy` (приватный ключ целиком, с `-----BEGIN…` и `-----END…`);
   - по желанию: `RECORDER_SSH_USER` (по умолчанию `root`), `RECORDER_SSH_PORT` (по умолчанию `22`), `RECORDER_SSH_KNOWN_HOSTS` (строка из `ssh-keyscan <IP>`; без неё отпечаток сервера берётся при каждом деплое).
4. Запустить Actions → «CI & Deploy» → Run workflow (или дождаться следующего мёржа). Шаг «Deploy recorder to the VPS» покажет последние строки лога записывалки; упавший контейнер делает шаг красным.
5. Руками на VPS: `docker logs -f vish-recorder` — лог, `docker restart vish-recorder` — перезапуск, слайды и кадры — в `/opt/vish-recorder/data`. **После правки `.env` restart не помогает**: Docker читает `--env-file` только при создании контейнера. Пересоздать (записи на диске не пропадут):
   ```
   docker rm -f vish-recorder && docker run -d --name vish-recorder --restart unless-stopped --init $(cat /opt/vish-recorder/docker.extra 2>/dev/null) --env-file /opt/vish-recorder/.env -v /opt/vish-recorder/data:/app/data --log-opt max-size=10m --log-opt max-file=3 vish-recorder:latest
   ```
   Или просто запустить деплой (Actions → «CI & Deploy» → Run workflow) — он пересоздаёт контейнер сам.

**Новая учётка для вебинаров (например, студент 4 курса).** Вебинар некоторых потоков пускает только своих студентов, поэтому для них заводят отдельный профиль: `WEBINAR_LOGIN_N`/`WEBINAR_PASSWORD_N`/`WEBINAR_GROUPS_N` (N от 2 до 9). Для пар этих групп сначала пробуется этот профиль, потом общий. Не делать во время вебинара: пересоздание контейнера обрывает идущую запись.
1. Зайти на VPS: `ssh -i <ключ> root@77.91.92.142`.
2. Копия на всякий случай: `cp /opt/vish-recorder/.env /opt/vish-recorder/.env.bak`.
3. `nano /opt/vish-recorder/.env` и дописать в конец (значения без кавычек и без пробелов вокруг `=`: Docker кавычки не снимает, и пароль в кавычках не подойдёт):
   ```
   WEBINAR_LOGIN_3=логин
   WEBINAR_PASSWORD_3=пароль
   WEBINAR_GROUPS_3=11-23,12-23,13-23,14-23
   ```
   Сохранить: Ctrl+O, Enter, выйти: Ctrl+X. Номер профиля — следующий свободный (`grep -n '^WEBINAR_LOGIN' /opt/vish-recorder/.env` покажет занятые). Если в `.env` задан непустой `RECORD_GROUPS`, туда тоже добавить эти группы, иначе их пары не записываются вовсе.
4. Пересоздать контейнер командой из пункта 5 выше (или запустить деплой).
5. Проверить: `docker logs vish-recorder --tail 20`. В строке «записывалка вебинаров запущена» в `profiles` должно появиться `3 (11-23, 12-23, 13-23, 14-23)` — там только номера и группы, без логинов. Ошибка «Профиль 3: нужны оба…» — не хватает логина или пароля. Когда начнётся пара этих групп, в строке «захожу на вебинар» будет `profile: "3"`.

`.env` деплой не трогает (в архив он не попадает), поэтому правка переживает все следующие обновления.

**Свои флаги `docker run` (`docker.extra`).** Если контейнеру нужен лишний флаг — например, адрес бота вручную, пока у его домена лежит DNS, — его пишут одной строкой в `/opt/vish-recorder/docker.extra`, и деплой добавляет его при каждом пересоздании:
```
echo "--add-host slides.secretvish.ru:135.125.188.210" > /opt/vish-recorder/docker.extra
```
DNS починили — файл удалить (`rm /opt/vish-recorder/docker.extra`) и пересоздать контейнер.

**Слоты студентов и ключ шифрования.** Заявки студентов на запись своих пар (этап 1) кладут учётки в `data/accounts.json` (права 0600, владелец root) — в нём логины и **пароли открытым текстом**, поэтому файл не копировать никуда, кроме бэкапа самого VPS. Ключ, которым записывалка расшифровывает заявки, — `data/keys/accounts.key` (0600). Бэкап `cp -a data/ …` теперь содержит и то, и другое — храни его как секрет. Потеря ключа не ломает уже заведённые слоты (пароли лежат рядом), но поданные и ещё не одобренные заявки придётся подать заново. Проверить, что ключ создался и лежит в томе (а не в `/app`, откуда его стёр бы деплой):
```
docker logs vish-recorder --since 10m | grep "ключ шифрования"
ls -la /opt/vish-recorder/data/keys/
```
Должны быть строка с путями `.../data/keys/accounts.key` и файл `accounts.key` с правами `-rw-------`.

**Перенести учётки студентов из `.env` в слоты.** Профили `WEBINAR_LOGIN_2 … _9` — это учётки студентов, заведённые руками. В слотах их видно в боте (`/slots`), раз в 6 часов они проверяются, о потере доступа приходит весть. Профиль 1 (общая учётка владельца) остаётся в `.env`. **Вне пар** (записывалка остановится примерно на минуту):
```
bash /opt/vish-recorder/app/deploy/env-to-slots.sh
```
Скрипт остановит контейнер, под каждым профилем войдёт в кабинет и узнает группу владельца, положит учётку в слот этой группы (группы профиля из `WEBINAR_GROUPS_N` сохраняются — поток, куда профиль заходил, остаётся), уберёт перенесённые профили из `.env` (копия — `.env.bak-…`, в ней пароли: после проверки `/slots` удалить) и поднимет контейнер заново. Профиль, у которого вход не прошёл, остаётся в `.env`. В `/slots` такие слоты подписаны «учётка из .env», у них те же «🔁 Проверить снова» и «🗑 Отозвать». Пересоздать контейнер без сборки (после любой правки `.env`) — `bash /opt/vish-recorder/app/deploy/vps-update.sh --recreate`.

**Подписать слот из `.env` владельцем.** Перенесённый слот сначала подписан «учётка из .env». Если знаешь, чья учётка: `/slot_owner 14-25 @ник`. Писал человек боту — слот становится обычным «его»: в `/slots` его ник, ему приходят вести о записи (приостановлена, снова работает, убрана), в «🗂 Ещё → 🎥 Запись моей группы» он видит статус и может отозвать сам; месячный лимит заявок это не тратит. Не писал — в `/slots` только подпись «@ник (из .env)»; когда нажмёт /start, повтори команду.

**Общая учётка (профиль 1) в `/slots`.** Она остаётся в `.env` (это ключ для всех групп без своей учётки) и видна в `/slots` строкой «🔑 Общая учётка (.env)»: раз в 6 часов записывалка проверяет, пускает ли она в кабинет (заход на пару тоже считается), состояние лежит в `data/general.json` без логина и пароля. Перестала пускать — придёт весть «поправь `WEBINAR_PASSWORD`» с кнопкой «🔁 Проверить снова»; на пары она при этом пробуется как раньше. Отозвать её кнопкой нельзя — только правкой `.env`. Проверяется лишь профиль в режиме «обучающийся» (`WEBINAR_AUTH=1`): кабинет сотрудника так не проверить.

**Кто идёт на пару, если подходит несколько учёток.** На каждую пару заходит один бот (одна пара — один ключ «дата + время + предмет + преподаватель», даже если портал покажет её несколькими строками). Учётки пробуются по очереди, пока портал не даст ссылку: сначала заведённые на группы этой пары — профили `.env` по номеру, затем слоты по алфавиту групп; последними — общие профили без групп. Не пустила (пароль сменили, не та группа) — следующая. Слоты, которые «не пускают», не пробуются, пока их не проверят заново. Сорвалась съёмка посреди пары — повтор начинается с начала очереди.

**Проверить учётку студента без вебинара.** Вход в личный кабинет lk.chuvsu.ru тем же логином и паролем, что у профиля в `.env`, и группа студента по расписанию. Печатает только «вход прошёл / не прошёл» и группу:
```
docker exec vish-recorder node dist/probe-account.js 3
```
(3 — номер профиля: `WEBINAR_LOGIN_3`). «Кабинет не ответил как обычно» — это сбой портала, а не неверный пароль.

**Вход для России (nginx на VPS).** Российские провайдеры режут соединения к хостингу бота (OVH, Франкфурт): кнопка формы в Telegram давала `ERR_CONNECTION_RESET`. Поэтому люди заходят через этот VPS (Москва): nginx принимает HTTPS на имена бота и пересылает запросы боту по HTTPS. Бот и база остаются на хостинге; меняется только A-запись имени.
1. Секреты на VPS (права 0600, в чат и репозиторий не класть):
   - `/root/.secrets/cloudflare.ini` — строка `dns_cloudflare_api_token = …` (Cloudflare → My Profile → API Tokens → шаблон «Edit zone DNS» на зону `frienworld.com`);
   - `/root/.secrets/selectel.env` — только если зона `secretvish.ru` на DNS Selectel (actual): `SL_Ver=v2`, `SL_Login_ID=<номер аккаунта>`, `SL_Project_Name=<проект с зоной>`, `SL_Login_Name=<сервисный пользователь>`, `SL_Pswd=<его пароль>`. Пользователю — роль «Администратор проекта» только в проекте с зоной; лучше отдельный проект под DNS.
2. `bash /opt/vish-recorder/app/deploy/setup-front.sh` (скрипт приезжает с деплоем записывалки). Ставит nginx, certbot, acme.sh, выпускает сертификаты через DNS (до смены A-записи — без простоя) и проверяет `/health` и `/tma` через сам VPS. В конце — `OK …` по каждому имени. Повторный запуск безопасен; контейнер записывалки не трогает.
   - Имена из `SEL_NAMES` (`calendar.secretvish.ru`): если NS домена — Selectel и есть `selectel.env`, сертификат выпускается через DNS, как выше. Иначе (сейчас NS у IHOR) — **через сайт** (HTTP-01): Let's Encrypt забирает файл проверки с этого VPS, поэтому порядок обратный — **сначала** A-запись имени на `77.91.92.142`, **потом** скрипт. Пока запись не указывает сюда, скрипт пишет «⏳ … переведи A-запись сюда» и имя пропускает. Между сменой записи и `OK` HTTPS по этому имени не работает (старые http-ссылки — работают). Не вышло — повторять не чаще раза в час: у Let's Encrypt лимит неудачных проверок.
3. После `OK` — A-запись имени на `77.91.92.142` (в Cloudflare облако **серое**: адреса Cloudflare в России тоже режут). Откат — вернуть прежний IP (`135.125.188.210`). `slides.secretvish.ru` на VPS не переводить: скрипт это имя не обслуживает, а записывалка и так стоит на VPS.
4. Когда у `calendar.secretvish.ru` появится сертификат — в `.env` бота `PUBLIC_URL=https://calendar.secretvish.ru`: новые ссылки пойдут по HTTPS, старые http-ссылки (`/cal/…`, и с портом `:40070`) VPS обслуживает как раньше.

Продление — само (таймер certbot, cron acme.sh). Лог: `/var/log/nginx/error.log`. Имена и адреса меняются переменными: `CF_NAMES`, `SEL_NAMES`, `BOT_IP`, `BOT_NAME`, `VPS_IP`, `LEGACY_HTTP_PORT` (см. начало скрипта).

**Страница «Кворум» (https://parlament.secretvish.ru/quorum).** Открытая страница: полукругом по группам ВИШ — сколько студентов уже в боте (зелёные) и сколько нет (красные). Страница и файл «сколько всего в группе» лежат на этом VPS (`recorder/deploy/quorum/`), а числа «в боте» она раз в минуту берёт у бота: `/quorum/live.json` nginx пересылает боту на `/quorum.json` (только названия групп и числа, без имён; студенты без заблокировавших бота и без режима преподавателя). Если в бот зашло больше людей, чем в списке группы, страница считает по боту (21/21, а не 21/20). Нужен уже работающий вход для России (`setup-front.sh`).
1. A-запись `parlament.secretvish.ru` → `77.91.92.142` (NS у IHOR — там же, где `calendar`).
2. Мёрж в `main` (не во время вебинара): бот получит `/quorum.json`, на VPS приедут страница и скрипт.
3. На VPS под root: `bash /opt/vish-recorder/app/deploy/setup-quorum.sh` — выпустит сертификат через сайт (HTTP-01), напишет `/etc/nginx/conf.d/vish-quorum.conf` (конфиг `setup-front.sh` не трогает) и в конце напечатает `OK https://parlament.secretvish.ru/quorum …`. Не вышло с сертификатом — повторять не чаще раза в час.
4. Сколько студентов в группе — `recorder/deploy/quorum/totals.json` в репозитории (`{"title": "ВИШ-12-26", "total": 29}`); правка выкладывается следующим деплоем записывалки сама. Группа, которой нет в файле, появится на странице, как только в боте будет хоть один её студент.
5. Гимн при открытии — `recorder/deploy/quorum/anthem.mp3` (громкость уже −20 dB в самом файле: на iPhone громкость из кода не меняется). Играет один раз на браузер; после перезагрузки — с того же места; справа сверху кнопка «Выключить звук» / «Включить звук» (выбор запоминается). До первого касания или клика по странице браузеры звук не дают — тогда гимн начинается с первым касанием. Состояние — в `localStorage` под ключом `vish-anthem-v1`: сменить ключ в `index.html` — и гимн сыграет у всех ещё раз. Отдаёт его nginx (`location = /quorum/anthem.mp3` в `setup-quorum.sh`); если в конфиге на VPS этой строки ещё нет, `vps-update.sh` при деплое сам один раз перезапустит `setup-quorum.sh`.

**Вариант Б — сервер в панели Pterodactyl.** Обычный Node-egg не годится: Chromium нужны системные библиотеки, а `npx playwright install --with-deps` ставит их через `apt` от root, которого в контейнере панели нет; к тому же yolks `nodejs_21` — это Node 21 (записывалке нужен ≥ 22.19), а `npx playwright` тянет чужую версию, не совпадающую с закреплённым `playwright-core`. Поэтому для панели есть свой образ — `ghcr.io/lomen-icarus/vish-recorder:latest` (`recorder/Dockerfile.ptero`: образ Playwright с Chromium и Node 24 плюс точка входа под Wings; кода в нём нет, код заливает workflow). Его собирает workflow «Recorder image» при изменении Dockerfile, точки входа или версии `playwright-core` (и вручную: Actions → Recorder image → Run workflow). Настройка:

1. Пакет `vish-recorder` в GitHub Packages должен быть публичным (Packages → vish-recorder → Package settings → Change visibility → Public), иначе узел панели его не скачает.
2. В панели как админ: Admin → Nests → нест записывалки → egg (например, node.js generic) → Docker Images → добавить строку `Vish recorder|ghcr.io/lomen-icarus/vish-recorder:latest` → Save. Затем у сервера: Startup → Image → выбрать её.
3. Startup Command сервера: `npm install && node dist/main.js` (лаунчера `index.js` у записывалки нет; браузер уже в образе, `playwright install` не нужен).
4. Build Configuration: память ≥ 1536 МБ (Chromium + комната BBB + Node), диск ≥ 3 ГБ (образ на узле, в файлы сервера идут только `node_modules`, слайды и кадры).
5. В файлах сервера — `.env` по `recorder/.env.example` (`PORTAL_LOGIN`/`PORTAL_PASSWORD`, `BOT_SLIDES_URL`, `SLIDES_TOKEN` — тот же, что у бота).
6. Секрет `PTERO_RECORDER_SERVER_ID` — короткий id сервера из адреса панели: `panel…/server/cf0acdc5` → `cf0acdc5` (8 символов, только они, без адреса). Сервер должен быть виден аккаунту, чей `PTERO_API_KEY`: чужой сервер панель отдаёт как 404. При 404 шаг печатает, какие id ключу видны. Номер VPS из биллинга сюда не подходит: выкладка идёт через API панели.

После этого каждый мёрж в `main` заливает `dist/` и `package.json` на сервер и перезапускает его; в консоли панели первой строкой — `node v24…, chromium из /ms-playwright`. Если заданы секреты `RECORDER_SSH_*`, путь через панель не запускается.

Общее для обоих:
- В `.env` записывалки: учётка для входа в комнату, `BOT_SLIDES_URL=https://<домен бота>/slides`, тот же `SLIDES_TOKEN`, что у бота (у бота он тоже должен быть задан, ≥ 16 символов).
- PDF записывалка шлёт целиком (лимит nginx хостинга перед ботом — 50 МБ, бот принимает до 40 МБ). Если прокси ответит 413 — например, лимит вернут к 1 МБ по умолчанию, — PDF сам уйдёт кусками по 900 КиБ (`/slides/part`, потом `/slides/complete` с контрольной суммой).
- Проверить разведкой во время живого вебинара: на VPS — `docker exec -it vish-recorder node dist/probe.js`, затем `docker exec -it vish-recorder node dist/probe.js join`.
- `MAX_PARALLEL` (по умолчанию `1`) — сколько пар записывать одновременно. Каждая запись — отдельный Chromium (пустой ≈ 0,4 ГБ, в комнате BBB больше): на одну запись нужно ≥ 1,5 ГБ памяти, на две — от 2,5–3 ГБ. У ВИШ одновременно идёт не больше одной онлайн-пары, так что `1` хватает.

### Inline-режим («@бот 12-23 завтра»)

Inline не работает, пока он не включён у самого бота: @BotFather → `/setinline` → выбрать бота → задать подсказку (например, `12-23 завтра`).
Пока он выключен, бот не обещает его в «Функциях», а в `/health` есть строка «Inline-режим: ВЫКЛЮЧЕН». После включения подсказка появляется в любом чате, включая группы, и прав администратора для этого не нужно.

### Режим преподавателя

1. Файл `data/teachers.csv`, по строке на человека: `ФИО;ник`. Первая строка может быть заголовком (`ФИО;Телеграм`), ник — с `@`, без него или ссылкой `t.me/…`; разделитель `;`, `,` или табуляция.
   ```
   ФИО;Телеграм
   Петрова Анна Сергеевна;@petrova_as
   ```
2. Залить файл на сервер в `/home/container/data/teachers.csv` (в git его нет). Бот перечитывает его сам, перезапуск не нужен.
3. Преподаватель открывает бота со своего аккаунта (`/start`) — бот узнаёт его по нику в реестре и сразу включает режим преподавателя: «Здравствуйте, Имя Отчество! Рад вас видеть», его пары на сегодня и предложение включить напоминания; группу выбирать не нужно. ФИО ищется в справочнике портала (при полных тёзках бот спрашивает, кто он). Дальше «Сегодня», «Завтра», «Неделя», напоминания, календарь, `/ask`, `/subjects` — по его парам. В «🔍 Найти» первая кнопка — «👥 Группы» (расписание любой группы). Выключить — `/prepod` (после этого `/start` режим сам не включает; `/prepod` — включает снова).
4. Кнопки, ведущей в режим, нет; команда видна только в меню админов. Админ может проверить режим на любом преподавателе: `/prepod Фамилия Имя Отчество`.
5. Без учётки портала (`PORTAL_LOGIN`) бот знает только онлайн-пары преподавателя со страницы вебинаров.

### Болталка в группах: пошагово

1. **Ключ.** Можно оставить общий `ANTHROPIC_API_KEY`. Отдельный ключ (Claude Console → API Keys → Create Key) удобен тем, что болталку тогда можно отключить или ограничить, не трогая `/ask`: `CHAT_ANTHROPIC_API_KEY=sk-ant-…`.
2. **Модель.** `CHAT_AI_MODEL` пусто — берётся `AI_MODEL`. Список моделей и цены: https://platform.claude.com/docs/en/about-claude/models/overview. Модели, которые не знают параметра `effort`, бот определяет сам.
3. **Включить.** Ничего делать не нужно: при заданном ключе болталка включена (`CHAT_AI=TRUE` по умолчанию). В консоли при запуске — строка `group chat enabled`. Выключить совсем — `CHAT_AI=FALSE`.
4. **Privacy mode.** По умолчанию Telegram в группах присылает боту только команды и ответы на его сообщения — «@бот привет» до него не дойдёт. Нужно: @BotFather → `/setprivacy` → выбрать бота → **Disable**, затем **удалить бота из группы и добавить снова** (без повторного добавления настройка в этой группе не применится). Другой путь — сделать бота админом группы: админы получают все сообщения. Проверить: `/health` → строка «Болталка в группах: … privacy mode выключен». Если бота не удаётся добавить в группу: @BotFather → `/setjoingroups` → Enable.
5. **Где болтать.** Добавь бота в группу сам (со своего аккаунта из `ADMIN_IDS`) — болталка там включится сразу. Если бота добавил кто-то другой, он там молчит, а админам в личку приходит «Меня добавили в чат …» с кнопкой «✅ Разрешить болтать». Ещё способы: `/chaton` / `/chatoff` прямо в чате (только админ бота), кнопки в `/chats` (= `/admin → 💬 Болталка`), id чата в `CHAT_GROUP_IDS`. В чатах из `NEWS_CHANNEL_IDS` бот не болтает: там он пересылает новости.
6. **Лимиты.** `/admin → 💬 Болталка`: ➖/➕ на человека, на чат и общий, «🚀 Сегодня +…» — разовая добавка на день, «♻️ Как в .env» — сброс. То же командой: `/chatlimit user 30`, `/chatlimit chat 200`, `/chatlimit global 500`, `/chatlimit boost 200`, `/chatlimit reset`. Админы бота болтают без лимита. О кончившемся лимите бот говорит один раз в день, дальше молчит.
7. **Сценарий.** См. ниже. Проверка: `/qa_test сосал?` покажет, какая заготовка подойдёт.

Как бот понимает, что обращаются к нему: `@бот …` в тексте или подписи к фото и ответ (reply) на его сообщение. Пересланное сообщение с `@бот` обращением не считается (чтобы чужой спам не жёг лимит). Между ответами в одном чате — пауза 3 секунды. Контекст ответа: прошлые реплики этого человека боту в этом чате (за 6 часов), недавняя переписка чата и сообщение, на которое человек ответил.

Про пары, аудитории, преподавателей, предметы и сам бот болталка отвечает по расписанию (те же инструменты, что у `/ask`; «что у меня завтра» — по группе, которую человек выбрал в личке). Про конкретных студентов в общем чате бот ничего не говорит: поиска людей у него там нет.

**Социальность** (всё — только в разрешённых чатах):

- Войдя в чат, бот пишет «Привет, а что это за группа?». Ответь на это сообщение (reply) — со своего аккаунта админа бота, админа чата или того, кто бота добавил, — и бот запомнит описание чата и будет учитывать его в ответах. Переспросить: `/chatabout` в чате.
- «@бот сюда слайды по физике» — в теме форума или в обычном чате. Бот уточнит точное название предмета и дату ближайшего вебинара и спросит «Ты хочешь получать …?» — нажми «✅ Да» (кнопка работает только у того, кто просил). Для чужой группы: «… по физике для 14-23». Отписка — «@бот не присылай сюда слайды по физике» (без предмета — всё сразу, после кнопки «Да»), список — «@бот какие слайды сюда приходят». Слайды в личку теперь у всех выключены по умолчанию (включаются в ⚙️ Настройках).
- «@бот скинь слайды по физике» — пришлёт последнюю запись (PDF); записи нет — предложит подписку. Модель тоже знает про слайды: как ни сформулируй, она вызовет тот же механизм.
- «@бот стоит ли собрание 12-23 в пятницу в 15:00?» — сверит время с парами группы.
- «@ник это Фамилия Имя 12-23» — бот запишет знакомство и сможет звать человека по имени (не при анонимности). Боту можно и своими словами: «@бот знакомься, это Фамилия Имя — @ник» или «@бот это Фамилия Имя» ответом на сообщение человека. Знакомства лежат в базе (`people_intros`), а не в файле студентов: список и удаление — `/intros`, `/intro_del N` в личке админа.
- «@бот, а сделай, чтобы…» — идея уходит админам в личку, список — `/ideas`.
- Ночью (23:00–05:00), если бота не трогали полчаса, он сначала сонно ворчит.

Что хранится: пары «реплика → ответ бота» (`chat_log`, 3 дня, стираются по `/soon`), расход по дням (`chat_usage`, как у `/ask`), описание чата (`meta`), подписки тем на слайды (`chat_slide_subs`), знакомства (`people_intros`, стираются по `/soon` того, о ком они), идеи (`feature_ideas`). Чужая переписка чата — только в памяти процесса и пропадает при перезапуске. В логах — только цифры: id чата, число токенов, совпала ли заготовка; ни имён, ни текста.

### Сценарий болталки: формат CSV

Ответ всегда пишет ИИ, а сценарий — его заготовки: если реплика совпадает с вопросом из базы (дословно, другими словами или с опечаткой), бот отвечает заготовкой — слово в слово или близко к тексту, подстроив под собеседника. Вся база лежит в системном промпте (с кешем), а заготовки, совпавшие по словам, дополнительно подсвечиваются в запросе.

```
вопрос;ответ;подсказка
# строки с # — комментарии
сосал?|ты сосал?|сосал ли ты;Здесь твой ответ;дословно
# ответ-гифка: file_id даёт бот (гифка с подписью «/qa_add вопрос = подпись» или /qa_fileid ответом на гифку)
ржака|смешно;gif:CgACAgIAAxkBAAI… держи;
как дела|как ты;Лучше всех, пока пары не начались;шутливо
кто тебя сделал;Студенты ВИШ, с любовью и кофе;
"вопрос; с точкой с запятой";"Ответ
в две строки";
```

- Колонки: вопрос, ответ, подсказка (необязательна: как отвечать — «дословно», «с сарказмом», «коротко»).
- Несколько вариантов вопроса — через `|`. Регистр, «ё» и знаки препинания не важны.
- Разделитель `;` (Excel), `,` (Google Таблицы → Файл → Скачать → CSV) или табуляция — бот определяет сам.
- Поле с `;`, кавычками или переносом строки — в двойных кавычках, кавычка внутри — `""`.
- Кодировка UTF-8; «CSV» от русского Excel в Windows-1251 тоже читается.
- До 2000 заготовок; в промпт попадают первые ~24 000 символов базы, остальные модель видит, только когда они совпали по словам.

Три способа наполнить:
1. Файлом на сервере: `/home/container/data/chat-qa.csv`. Бот замечает изменения сам, перезапуск не нужен.
2. Из бота по одной: `/qa_add сосал? | ты сосал? = Твой ответ = дословно` (третья часть — подсказка, необязательна).
3. Файлом через бота: `/qa_file` — бот пришлёт текущий CSV, поправь и отправь обратно командой `/qa_import` (или документом с подписью `/qa_import`). Старая версия остаётся рядом как `chat-qa.csv.bak`; пустой или нечитаемый файл бот не примет.

`/qa` — сколько заготовок загружено, ошибки файла, список с номерами и эта шпаргалка. `/qa_del 3` или `/qa_del вопрос` — удалить заготовку.

Команды первой версии бота в группах работают как раньше: `/chats` (экран болталки), `/replies` (= `/qa`), `/reply_add вопрос => ответ` (после `=>` ответ берётся целиком, можно многострочный), `/reply_del`. Ответы, добавленные через старый `/reply_add`, при первом запуске новой версии сами переезжают в файл сценария с подсказкой «дословно»; включённые чаты и лимит на чат тоже переносятся.

## Бот в МАКС

Тот же бот, та же база и те же функции работают и в мессенджере МАКС (мост `src/max/`, решение №139).

1. Бот в МАКС создаётся на business.max.ru (нужен верифицированный профиль ИП или организации), после модерации токен — «Чат-боты» → бот → «⋮» → «Настройки».
2. В `/home/container/.env` на сервере бота: `MAX_BOT_TOKEN=токен` (без кавычек) и перезапуск.
3. В логе при старте — `MAX bot authorised` (id и ник бота в МАКС) и `polling MAX for updates`. `MAX_BOT_TOKEN не подходит (401)` — токен скопирован не целиком или выпущен заново. `MAX bridge not started` — МАКС не ответил; Telegram при этом работает как обычно.
4. Проверка: найти бота в МАКС по нику `id<ИНН>_bot`, нажать «Начать», выбрать группу, «📅 Сегодня».

Что в МАКС не так, как в Telegram: нижнего меню нет — те же кнопки стоят под сообщениями; нет inline-режима («@бот 12-23» в чатах), мини-приложения записи и групповых чатов. Корень сертификата Минцифры для API МАКС уже вшит в код, ставить его на сервер не нужно.

## Порт и подписка на календарь

Pterodactyl передаёт выделенный порт в переменной `SERVER_PORT`; бот поднимает на нём HTTP-сервер с личными лентами календаря (`/cal/<token>.ics`) и `/health`.
Чтобы в боте появилась кнопка «Подписка», в `.env` нужно добавить адрес, по которому этот порт виден снаружи: `PUBLIC_URL=http://srv3.frienworld.space:40070`.
Проверка: открыть `http://srv3.frienworld.space:40070/health` в браузере — должен вернуться JSON с `"ok":true`. Если порт снаружи закрыт, подписка не работает, файл .ics работает всегда.

## Первый запуск вручную

1. В панели создать файл `.env` по образцу `.env.example`.
2. Залить релиз: `npm run build`, затем загрузить `index.js`, `dist/`, `package.json`, `package-lock.json` и `.npmrc` с содержимым `omit=dev` (или запустить workflow `CI & Deploy` вручную: Actions → Run workflow, он собирает всё сам).
3. Нажать Start. В консоли должны появиться строки `bot authorised`, `scheduler started`, `poll finished`.
4. Написать боту `/start`, затем `/health` (для администратора) — покажет аптайм, последний опрос и калибровку недели.

## Node 18 в egg'е

Образ `ghcr.io/parkervcp/yolks:nodejs_18` слишком старый для зависимостей (undici 8 требует Node 22.19+, база данных использует встроенный `node:sqlite`).
Лаунчер `index.js` это обходит: один раз скачивает портативный Node 22 с nodejs.org в `.runtime/` и ставит зависимости им.
Лучше попросить FrienWorld добавить образ `ghcr.io/parkervcp/yolks:nodejs_22` в egg и переключиться на него — тогда обход не нужен.

Важно: контейнер FrienWorld запрещает `utime()` на файлах (ошибка `EPERM: operation not permitted, futime`), поэтому нативные модули там не собираются вообще.
В проекте их нет: SQLite встроен в Node, `@resvg/resvg-js` ставится готовым бинарником как обычный npm-пакет. Не добавляйте зависимости с `node-gyp`.

Нужны три секрета в GitHub (см. таблицу выше). `PTERO_PANEL_URL` = `https://panel.frienworld.space`, `PTERO_SERVER_ID` = `b7f95b74`.

## Бэкап

База — один файл `data/vish-bot.sqlite` (WAL-режим, рядом могут лежать `-wal` и `-shm`). Бэкап панели («Backups», 1 слот) его покрывает; для ручной копии остановите бот или скопируйте все три файла вместе.
