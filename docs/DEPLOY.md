# Деплой на Pterodactyl (FrienWorld)

Сервер: панель `panel.frienworld.space`, сервер `b7f95b74`, egg **Node.js generic**, порт `srv3.frienworld.space:40070`.
Бот работает через long polling; открытый порт нужен только подписке на календарь (маленький HTTP-сервер, HTTPS не требуется).

## Что лежит на сервере

```
/home/container
├── index.js          # лаунчер: запускает dist/main.js, при Node < 22.19 скачивает портативный Node 22 в .runtime/
├── dist/             # собранный бот (npm run build)
├── package.json      # зависимости ставятся стартовым скриптом egg'а (npm install)
├── .env              # секреты, создаётся вручную в файловом менеджере панели
└── data/             # SQLite-база (vish-bot.sqlite), бэкапится копированием файла
```

Стартовая команда egg'а уже подходит: `npm install` + `node /home/container/index.js` (переменная `JS_FILE=index.js`).

### Реестр студентов для «сыска»

Файл с людьми **никогда не коммитится в GitHub** — он едет прямо на сервер:

1. Собрать CSV из выгрузок Excel: `node scripts/students-from-xlsx.mjs data/students.csv реестр.xlsx база.xlsx`
   (скрипт читает только два столбца — ФИО и группу; телефоны, почты, баллы и документы он не открывает и в файл не пишет; имён в консоль не печатает).
2. Залить `students.csv` в панели в `/home/container/data/students.csv`.
3. В `.env`: `POISK=TRUE`, `POISK_DB=./data/students.csv`.
4. Проверить в боте: `/health` → строка «Сыск (поиск студентов)» покажет, сколько человек прочитано и сколько поисков было за сегодня.

Файл можно менять на ходу: бот замечает новый `mtime`/размер и перечитывает его сам, перезапуск не нужен.
Формат — `ФИО;Группа` (первая строка заголовок). Понимаются также JSON (`[{"fio":…,"group":…}]`) и SQLite-файл с таблицей, где есть столбцы ФИО и группы.

### Второй сервер: запись вебинаров

`recorder/` — самостоятельный сервис с браузером внутри. Ему нужно ≥ 1.5 ГБ памяти и Chromium, поэтому он живёт не рядом с ботом, а на своём контейнере (`panel.frienworld.space`, сервер записи).

1. В GitHub → Secrets добавить `PTERO_RECORDER_SERVER_ID` — id второго сервера. Пока секрета нет, шаг деплоя записи просто пропускается.
2. На сервере записи положить `.env` по образцу `recorder/.env.example`: учётка для входа в комнату, `BOT_SLIDES_URL=http://<адрес бота>:40070/slides`, тот же `SLIDES_TOKEN`.
3. Поставить браузер: `npx playwright install chromium --with-deps` (или запускать образ из `recorder/Dockerfile`, там Chromium уже есть).
4. Проверить разведкой во время живого вебинара: `npm run probe`, затем `npm run probe -- join`.
5. `MAX_PARALLEL` (по умолчанию `2`) — сколько пар записывать одновременно. Каждая запись — отдельный Chromium: если памяти на сервере записи хватает только на один браузер, поставить `MAX_PARALLEL=1`, тогда параллельная пара ждёт, пока освободится место.

### Inline-режим («@бот 12-23 завтра»)

Inline не работает, пока он не включён у самого бота: @BotFather → `/setinline` → выбрать бота → задать подсказку (например, `12-23 завтра`).
Пока он выключен, бот не обещает его в «Функциях», а в `/health` есть строка «Inline-режим: ВЫКЛЮЧЕН». После включения подсказка появляется в любом чате, включая группы, и прав администратора для этого не нужно.

### Режим преподавателя

1. Файл `data/teachers.csv`, по строке на человека: `ФИО;ник`. Первая строка может быть заголовком (`ФИО;Телеграм`), ник — с `@`, без него или ссылкой `t.me/…`; разделитель `;`, `,` или табуляция.
   ```
   ФИО;Телеграм
   Петрова Анна Сергеевна;@petrova_as
   ```
2. Залить файл на сервер в `/home/container/data/teachers.csv` (в git его нет). Бот перечитывает его сам, перезапуск не нужен.
3. Преподаватель открывает бота со своего аккаунта (`/start`) — бот узнаёт его по нику в реестре и сразу включает режим преподавателя: «Здравствуйте, Имя Отчество! Рад вас видеть», его пары на сегодня и предложение включить напоминания; группу выбирать не нужно. ФИО ищется в справочнике портала (при полных тёзках бот спрашивает, кто он). Дальше «Сегодня», «Завтра», «Неделя», напоминания, календарь, `/ask`, `/subjects` — по его парам. Третья кнопка меню — «👥 Студенты» (то же, что «Др. группы»). Выключить — `/prepod` (после этого `/start` режим сам не включает; `/prepod` — включает снова).
4. Кнопки, ведущей в режим, нет; команда видна только в меню админов. Админ может проверить режим на любом преподавателе: `/prepod Фамилия Имя Отчество`.
5. Без учётки портала (`PORTAL_LOGIN`) бот знает только онлайн-пары преподавателя со страницы вебинаров.

### Болталка в группах: пошагово

1. **Ключ.** Можно оставить общий `ANTHROPIC_API_KEY`. Отдельный ключ (Claude Console → API Keys → Create Key) удобен тем, что болталку тогда можно отключить или ограничить, не трогая `/ask`: `CHAT_ANTHROPIC_API_KEY=sk-ant-…`.
2. **Модель.** `CHAT_AI_MODEL` пусто — берётся `AI_MODEL`. Список моделей и цены: https://platform.claude.com/docs/en/about-claude/models/overview. Модели, которые не знают параметра `effort`, бот определяет сам.
3. **Включить.** Ничего делать не нужно: при заданном ключе болталка включена (`CHAT_AI=TRUE` по умолчанию). В консоли при запуске — строка `group chat enabled`. Выключить совсем — `CHAT_AI=FALSE`.
4. **Privacy mode.** По умолчанию Telegram в группах присылает боту только команды и ответы на его сообщения — «@бот привет» до него не дойдёт. Нужно: @BotFather → `/setprivacy` → выбрать бота → **Disable**, затем **удалить бота из группы и добавить снова** (без повторного добавления настройка в этой группе не применится). Другой путь — сделать бота админом группы: админы получают все сообщения. Проверить: `/health` → строка «Болталка в группах: … privacy mode выключен». Если бота не удаётся добавить в группу: @BotFather → `/setjoingroups` → Enable.
5. **Где болтать.** Добавь бота в группу сам (со своего аккаунта из `ADMIN_IDS`) — болталка там включится сразу. Если бота добавил кто-то другой, он там молчит, а админам в личку приходит «Меня добавили в чат …» с кнопкой «✅ Разрешить болтать». Ещё способы: `/chaton` / `/chatoff` прямо в чате (только админ бота), кнопки в `/chats` (= `/admin → 💬 Болталка`), id чата в `CHAT_GROUP_IDS`. В чатах из `NEWS_CHANNEL_IDS` бот не болтает: там он пересылает новости.
6. **Лимиты.** `/admin → 💬 Болталка`: ➖/➕ на человека, на чат и общий, «🚀 Сегодня +…» — разовая добавка на день, «♻️ Как в .env» — сброс. То же командой: `/chatlimit user 30`, `/chatlimit chat 200`, `/chatlimit global 500`, `/chatlimit boost 200`, `/chatlimit reset`. Админы бота болтают без лимита. О кончившемся лимите бот говорит один раз в день, дальше молчит.
7. **Сценарий.** См. ниже. Проверка: `/qa_test сосал?` покажет, какая заготовка подойдёт.

Как бот понимает, что обращаются к нему: `@бот …` в тексте или подписи к фото и ответ (reply) на его сообщение. Пересланное сообщение с `@бот` обращением не считается (чтобы чужой спам не жёг лимит). Между ответами в одном чате — пауза 3 секунды. Контекст ответа: прошлые реплики этого человека боту в этом чате (за 6 часов), недавняя переписка чата и сообщение, на которое человек ответил.

Про пары, аудитории, преподавателей, предметы и сам бот болталка отвечает по расписанию (те же инструменты, что у `/ask`; «что у меня завтра» — по группе, которую человек выбрал в личке). Про конкретных студентов в общем чате бот ничего не говорит: поиска людей у него там нет.

Что хранится: пары «реплика → ответ бота» (`chat_log`, 3 дня, стираются по `/soon`), расход по дням (`chat_usage`, как у `/ask`). Чужая переписка чата — только в памяти процесса и пропадает при перезапуске. В логах — только цифры: id чата, число токенов, совпала ли заготовка; ни имён, ни текста.

### Сценарий болталки: формат CSV

Ответ всегда пишет ИИ, а сценарий — его заготовки: если реплика совпадает с вопросом из базы (дословно, другими словами или с опечаткой), бот отвечает заготовкой — слово в слово или близко к тексту, подстроив под собеседника. Вся база лежит в системном промпте (с кешем), а заготовки, совпавшие по словам, дополнительно подсвечиваются в запросе.

```
вопрос;ответ;подсказка
# строки с # — комментарии
сосал?|ты сосал?|сосал ли ты;Здесь твой ответ;дословно
как дела|как ты;Лучше всех, пока пары не начались;шутливо
кто тебя сделал;Студенты ВИШ, с любовью и кофе;
"вопрос; с точкой с запятой";"Ответ
в две строки";
```

- Колонки: вопрос, ответ, подсказка (необязательна: как отвечать — «дословно», «с сарказмом», «коротко»).
- Несколько вариантов вопроса — через `|`. Регистр, «ё» и знаки препинания не важны.
- Разделитель `;` (Excel), `,` (Google Таблицы → Файл → Скачать → CSV) или табуляция — бот определяет сам.
- Поле с `;`, кавычками или переносом строки — в двойных кавычках, кавычка внутри — `""`.
- Кодировка UTF-8; «CSV» от русского Excel в Windows-1251 тоже читается.
- До 2000 заготовок; в промпт попадают первые ~24 000 символов базы, остальные модель видит, только когда они совпали по словам.

Три способа наполнить:
1. Файлом на сервере: `/home/container/data/chat-qa.csv`. Бот замечает изменения сам, перезапуск не нужен.
2. Из бота по одной: `/qa_add сосал? | ты сосал? = Твой ответ = дословно` (третья часть — подсказка, необязательна).
3. Файлом через бота: `/qa_file` — бот пришлёт текущий CSV, поправь и отправь обратно командой `/qa_import` (или документом с подписью `/qa_import`). Старая версия остаётся рядом как `chat-qa.csv.bak`; пустой или нечитаемый файл бот не примет.

`/qa` — сколько заготовок загружено, ошибки файла, список с номерами и эта шпаргалка. `/qa_del 3` или `/qa_del вопрос` — удалить заготовку.

Команды первой версии бота в группах работают как раньше: `/chats` (экран болталки), `/replies` (= `/qa`), `/reply_add вопрос => ответ` (после `=>` ответ берётся целиком, можно многострочный), `/reply_del`. Ответы, добавленные через старый `/reply_add`, при первом запуске новой версии сами переезжают в файл сценария с подсказкой «дословно»; включённые чаты и лимит на чат тоже переносятся.

## Порт и подписка на календарь

Pterodactyl передаёт выделенный порт в переменной `SERVER_PORT`; бот поднимает на нём HTTP-сервер с личными лентами календаря (`/cal/<token>.ics`) и `/health`.
Чтобы в боте появилась кнопка «Подписка», в `.env` нужно добавить адрес, по которому этот порт виден снаружи: `PUBLIC_URL=http://srv3.frienworld.space:40070`.
Проверка: открыть `http://srv3.frienworld.space:40070/health` в браузере — должен вернуться JSON с `"ok":true`. Если порт снаружи закрыт, подписка не работает, файл .ics работает всегда.

## Первый запуск вручную

1. В панели создать файл `.env` по образцу `.env.example`.
2. Залить релиз: `npm run build`, затем загрузить `index.js`, `dist/`, `package.json`, `package-lock.json` и `.npmrc` с содержимым `omit=dev` (или запустить workflow `CI & Deploy` вручную: Actions → Run workflow, он собирает всё сам).
3. Нажать Start. В консоли должны появиться строки `bot authorised`, `scheduler started`, `poll finished`.
4. Написать боту `/start`, затем `/health` (для администратора) — покажет аптайм, последний опрос и калибровку недели.

## Node 18 в egg'е

Образ `ghcr.io/parkervcp/yolks:nodejs_18` слишком старый для зависимостей (undici 8 требует Node 22.19+, база данных использует встроенный `node:sqlite`).
Лаунчер `index.js` это обходит: один раз скачивает портативный Node 22 с nodejs.org в `.runtime/` и ставит зависимости им.
Лучше попросить FrienWorld добавить образ `ghcr.io/parkervcp/yolks:nodejs_22` в egg и переключиться на него — тогда обход не нужен.

Важно: контейнер FrienWorld запрещает `utime()` на файлах (ошибка `EPERM: operation not permitted, futime`), поэтому нативные модули там не собираются вообще.
В проекте их нет: SQLite встроен в Node, `@resvg/resvg-js` ставится готовым бинарником как обычный npm-пакет. Не добавляйте зависимости с `node-gyp`.

## Автодеплой

Workflow `.github/workflows/deploy.yml`: на каждый push в `main` прогоняет typecheck, тесты, сборку, затем загружает архив через Client API панели, распаковывает его в корень и перезапускает сервер.
