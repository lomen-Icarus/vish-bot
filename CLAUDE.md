# vish-bot — правила для работы над ботом

Telegram-бот расписания ВИШ ЧувГУ. Подробности: `README.md`, решения — `docs/DECISIONS.md`, деплой — `docs/DEPLOY.md`.
Отвечать владельцу по-русски, коротко и по делу; о сделанном — в формате «было → стало».

## Пользовательский путь — главное правило интерфейса

Любую кнопку, экран, текст или предложение оцениваем по пути человека к его цели.

Понятия:
- **Пользовательский путь (user journey)** — вся история человека с ботом: зачем пришёл, что делает, где застревает.
- **Сценарий (user flow / task flow)** — шаги до одной цели: «где завтра первая пара», «расписание препода».
- **Цена взаимодействия (interaction cost, NN/g)** — все усилия на пути: прочитать, найти, понять, нажать,
  напечатать, подождать, запомнить. Уменьшаем общую цену, а не только число нажатий.
- **Информационный след (information scent, NN/g)** — по подписи кнопки сразу ясно, что за ней.
- **«Правило трёх кликов» — миф (NN/g)**: важны уверенность на каждом шаге и общая цена, а не число.
- **Закон Теслера**: сложность не исчезает — её забирает бот (умолчания, догадки), а не человек.
- **Эвристика №8 Нильсена**: каждая лишняя кнопка и строка отнимает видимость у нужного — без свалки.

Чек-лист (каждый пункт проверять перед тем, как предлагать или делать):
1. Цель и частота. Ежедневное — 1 нажатие; еженедельное — не больше 2; редкое (настройки) — не больше 3 и без поиска.
2. Считать путь: нажатия + сообщения + ввод + места, где можно ошибиться. В предложении писать путь «было → стало».
3. Подпись — обещание: слова студента, а не внутренние термины («Поток», «Сессия: выкл» — плохо; пояснение — одной строкой).
4. Не больше двух уровней; в панели не больше 6 кнопок.
5. Без свалки: в главное меню — только с доказанной частотой (счётчики нажатий в /stats); остальное — в панели или по месту.
6. Нужная кнопка в нужный момент: следующее действие — под результатом (стрелки, «что изменилось»).
7. Сложность — на боте: разумные умолчания, бот понимает «14-24», «послезавтра», фамилию; лишнего не спрашивать.
8. Ничего важного без явного действия: ИИ-лимит не тратится сам, обращение уходит только по «Отправить».
9. Обратимость: «↩️ Вернуть», «◀️ Назад», отмена.
10. Одна функция — один вход в меню (текст и команда — запасные пути, не лишние кнопки).
11. Проверка на людях: 5 студентов × 5 задач, счётчики до/после; не A/B на ~110 пользователях.

## Постоянные правила проекта
- Не мёржить, пока идёт вебинар (записывалка перезапускается при деплое).
- Секреты — только `.env` / GitHub Secrets; реестры людей (старосты, студенты, преподаватели) — только на сервере.
- В логах — только id и цифры, без имён и текста сообщений. Репозиторий публичный: в логи Actions ничего личного.
- Миграции БД — только дописывать в конец `src/db/migrations.ts`.
- Перед пушем: `npm run typecheck`, `npm test`, `npm run build`, `tsc` в `recorder/`.
